# CLIオプション結合テスト計画

## 目的
`Program` を起点に、CLI引数の受け取りから実行結果（終了可否・出力ファイル・エラーメッセージ）までを結合レベルで検証する。

## 前提
- 単体テスト（`ArgumentParserTests`）は既存。
- 本計画では「パーサー単体」ではなく「CLI実行フロー全体」を対象にする。

## テスト観点
1. 正常系の引数解釈
- 必須引数（入力パス）だけで実行できること。
- `--output` 指定時にJSONファイルが生成されること。

2. オプション併用時の成立性
- `--rules` / `--filter` / `--exclude` を併用しても実行が成立すること。
- `--filter` は現状未適用のため、値を受理して処理継続できることを確認する。

3. 異常系
- 未知オプション指定時に失敗し、期待メッセージが得られること。
- 必須引数不足時に失敗し、Usage系メッセージが得られること。

4. ファイル出力の妥当性
- `--output` 未指定時は標準出力に結果が出ること。
- `--output` 指定時はファイルへ出力されること。

## 作成予定テスト
| テストID | 種別 | 観点 | 入力例 | 期待結果 |
|---|---|---|---|---|
| CIT-01 | 正常系 | 必須引数のみ | `<inputPath>` | 例外なしで完了 |
| CIT-02 | 正常系 | `--output` | `<inputPath> --output out.json` | `out.json` が生成される |
| CIT-03 | 正常系 | 主要オプション併用 | `<inputPath> --rules rules.json --filter ns:* --exclude *Tests*` | 例外なしで完了 |
| CIT-04 | 異常系 | 未知オプション | `<inputPath> --unknown x` | 失敗し未知オプション文言を含む |
| CIT-05 | 異常系 | 必須引数不足 | `--output out.json` | 失敗しUsage文言を含む |
| CIT-06 | 正常系 | 出力先切替 | `<inputPath>` / `<inputPath> --output out.json` | 前者は標準出力、後者はファイル出力 |

## 実装方針
- テストプロジェクト内で最小入力プロジェクトを一時ディレクトリに生成する。
- `Program.Main` を直接呼び出せる形を優先し、必要に応じて標準出力を捕捉する。
- OS依存の挙動を避けるため、改行コードやパス区切り差は吸収する。
- テストデータ作成の共通方針は `docs/workflow/testing.md` を参照する。

## 完了条件
- 上記テストIDのうち優先度高（CIT-01〜CIT-05）を実装し、`dotnet test` でPassする。
- `docs/workflow/testing.md` にテスト分類とケースを反映する。
